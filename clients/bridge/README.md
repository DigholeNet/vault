# vault-bridge

UniFFI bridge crate exposing `vault-core`'s client session (`ClientSession`)
to the mobile clients of the [Vault VPN](../../README.md) system. Shared by:

- **Android** (`clients/android`): built as a cdylib (`libvault_bridge.so`)
  per ABI; the Kotlin bindings generated by UniFFI are loaded via JNA.
- **Apple** (`clients/apple`): built as a staticlib per target triple and
  packaged into `VaultCoreFFI.xcframework` by
  `clients/apple/VaultCore/Scripts/build-xcframework.sh`, together with the
  UniFFI-generated Swift bindings.

All VPN client logic (handshake, heartbeat, reconnect, crypto, data pump)
lives in [`vault-core`](../../core) (`client` feature); this crate only maps
the API to UniFFI and adds small platform glue (shared file logger, TUN fd
blocking mode).

## Exported API

- `RustEdge` — client session handle (connect, write packets, close)
- `EdgeCallbacks` — packet delivery, status and error callbacks into the app
- `TrafficStats`, `VpnError` — statistics and error types
- `set_log_file_path` — point the Rust logger at the app's shared log file

## Bindgen

The `bindgen` feature builds the `uniffi-bindgen` binary that the platform
build scripts use to (re)generate the Kotlin/Swift bindings:

```bash
cargo run -p vault-bridge --features bindgen --bin uniffi-bindgen -- --help
```

The generated bindings are build artifacts and are not committed.

## Tests

```bash
cargo test -p vault-bridge
```

The integration test (`tests/handshake.rs`) runs a full handshake against
the mock server from `vault-core`'s `test` feature.
