supernode(1)
============

== Name
supernode - Vault VPN server

== Synopsis
*supernode* --config <FILE> [OPTIONS]

*supernode* -s quit

== Description
supernode is the Vault VPN server. It accepts encrypted tunnels from
edge clients over UDP (SPAKE2 password-authenticated handshake, X25519 ECDH
key exchange, AEAD encryption), assigns each client an address from the configured pools,
relays traffic between clients and the public internet (NAT), and answers
heartbeat pings.

== Host network setup
The server automatically enables *net.ipv4.ip_forward=1* for an IPv4 pool and
*net.ipv6.conf.all.forwarding=1* for an IPv6 pool when needed at startup.
For IPv4, it then sets *net.ipv4.conf.all.send_redirects=0* and disables redirect
sending on its TUN to prevent ICMP Redirect messages during client-to-client relay.
Before enabling IPv6 forwarding, it changes exit interfaces with *accept_ra=1*
to *accept_ra=2* to preserve RA reception; disabled RA stays disabled. It also
disables IPv6 redirect acceptance on its TUN. Only configured address families
are changed. Required sysctl read/write failures abort startup.

Forwarding, global IPv4 redirect, and uplink RA changes remain after shutdown or
failed startup because other services or server instances may depend on them.

Exit interfaces come from usable default, connected and static routes, including
virtual uplinks. LAN-only deployments do not need a default route. Routes must be
present at startup; restart after changing exit interfaces.

Changing IPv4 *ip_forward* resets other IPv4 tunables. Hosts with custom settings
can provision forwarding before applying those tunables; see the supernode README.

== Options
*--config* <FILE>::
    Read configuration options from the specified TOML file.

*--log-dir* <DIR>::
    Write logs to this directory (default: /var/log/vault/). Logs are written
    only to files, including in foreground mode. Current log files have no date suffix (for example, default.log). On the
    first write after a UTC date change, the old file is archived with its
    last-write date (default.log.YYYY-MM-DD). Each stream keeps at most 30
    files, including the
    current file; older files are removed when that stream is initialized or
    rotates. This is a file-count limit, not a size or age limit.

*--daemon*::
    Run the process in the background.

*--pid-file* <FILE>::
    Store the process id in this file when daemonizing.

*--user* <USER>::
    After reading the configuration and acquiring the control socket, switch to this user before starting background threads. Requires starting as root. The log directory must support file creation, append, rename and deletion.

*--group* <GROUP>::
    Run as other group. Requires starting as root when changing identity.

The process retains CAP_NET_ADMIN, CAP_NET_BIND_SERVICE, CAP_NET_RAW and CAP_DAC_OVERRIDE for network setup, privileged ports and cleanup. This option changes identity but is not a complete privilege sandbox. Debian systemd services instead start directly as the dedicated *vault* user and group with these capabilities supplied by systemd.

*-s* <S>::
    Send a control signal to a running instance. Only *quit* is supported.

*-v, --verbose*::
    Print debug information.

*-q, --quiet*::
    Only print errors and warnings.

*--version*::
    Print the version and exit.

*-h, --help*::
    Print help information.

== Files
*/etc/vault/supernode.toml*::
    Configuration file. See *supernode.toml.example* for the available
    options (password, port, iface, ipv4/ipv6 pools).

*/run/supernode.socket*::
    Unix datagram socket used to deliver the quit signal to a running
    instance.

*/run/supernode.socket.lock*::
    Persistent file used for the process-lifetime instance lock. Duplicate
    starts cannot replace an active control socket. Do not delete the lock
    file while the service is running.
